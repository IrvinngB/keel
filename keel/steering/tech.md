# Tech
Last refreshed: 2026-09-24

## Stack

- JavaScript on Node.js >=18 (`engines`), no framework, no TypeScript.
- Zero runtime dependencies (WHY: portable, `npx` works with nothing to install, small
  supply-chain surface). `bin/sdd` and `build/generate.js` use only Node built-ins.
- Package `keel-sdd` 0.4.1, bin `sdd` -> `bin/sdd`, published files: bin, build, core,
  adapters, hooks.
- Also shipped as a Claude Code plugin (`sdd@keel`) via `.claude-plugin/marketplace.json`.

## Settled decisions

- `core/` is the single source of truth: tool-agnostic markdown contracts. No agent names,
  slash syntax or tool paths there; use placeholders `{{cmd:X}}`, `{{agent:X}}`, `{{skill:X}}`
  resolved by the registry (WHY: one contract serves every agent).
- `adapters/` is generated by `build/generate.js` (`node bin/sdd build`, runs a self-check).
  Never hand-edit; CI rejects stale output.
- Adding an agent = one row in `registry` in `build/manifest.json`; core never changes.
- Skill bodies stay invocation-neutral ("phase `sdd-apply`", not `/sdd:continue`).
- Never delete user files: install and doctor warn only.
- Status honesty: `verified` only after checking official docs; "Tested" only after a real
  session; inferred items go in `unverifiedFields`.
- Backend for this repo: `files` (`artifact_store: files`), artifacts in `keel/`.
- Keel develops itself with the RELEASED Keel, not this working copy (like a compiler built
  by its previous release).
- Version is kept in `package.json`, `build/manifest.json`, `.claude-plugin/marketplace.json`;
  a test fails if they disagree (`scripts/sync-version.js` syncs).

## Testing and quality

- Strict TDD: ON (`strict_tdd: true`). Security review: OFF (`security_review: false`).
- Runner: `node:test`, zero dependencies. Tests run the real CLI against throwaway git repos
  with an isolated `HOME`.
- Full: `npm test` (`node --test`). Focused: `node --test test/<file>.test.js`.
- Lint: none. Typecheck: none.
- A bug fix in `bin/sdd` must ship with a test that fails without it.
- CI: Linux, macOS, Windows; Node 18 and 22.
- `docs.test.js` checks `docs/es/` structure matches README / install / CONTRIBUTING.

## Commands

- `npm test`; `node bin/sdd build` (or `npm run build`) regenerates `adapters/`.
- Check: `git status --porcelain adapters/` must be empty after committing the rebuild.
- `node bin/sdd guard install`: once per clone; blocks commits while `keel/changes/` has
  unchecked tasks. Bypass deliberately: `SDD_ALLOW_COMMIT=1 git commit ...`.
- Install Keel for local agents with `--user` scope so `sdd install` does not write blocks
  into the tracked `AGENTS.md`.

## Git and release flow

- Conventional Commits. Regenerated adapters go in a separate `build: regenerate adapters`
  commit. PRs under ~400 changed lines excluding `adapters/`; else stacked PRs.
- User-visible changes get a line under `Unreleased` in `CHANGELOG.md`.
- Release: `npm version <patch|minor> --no-git-tag-version` -> date changelog, commit
  `chore: release X.Y.Z`, PR, merge -> annotated tag `vX.Y.Z` + `gh release create` ->
  `npm publish` from a clean tag checkout (`prepublishOnly` runs tests and refuses stale
  `adapters/`). After release, update the installed plugin before the next change.
